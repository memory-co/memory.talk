# services/work —— 做事层

work 树、画布、工作单元(现场)、谁在看、round、轨迹、收件箱(设计:[work.md](../../../../docs/designs/v5/work.md)、[worklet.md](../../../../docs/designs/v5/worklet.md)、[work-store.md](../../../../docs/designs/v5/work-store.md)、[work-trace.md](../../../../docs/designs/v5/work-trace.md))。记录在两个 sqlite 里,不进 git:`works.db` 管现在,`worktrace.db` 管经过。`__init__.py` 的 `WorkService` 是门面,其余每个文件管一种记录。

**一个动作的写法**:先在 `works.db` 一个事务里把读-改-写做完(`repo.tx()`,持 provider 的锁);建 / 销毁现场不在事务里;最后写 `worktrace.db`。两个库之间没有原子提交,轨迹写失败只记日志(`_record`),不让动作失败,也不回滚 work。

**同一个 work 的生命周期动作排队**(`_lifecycle`,每个 work 一把进程内的锁,不是 `works.db` 事务):`update`(从改状态的事务到归档收尾 / 开新段做完)、`attach`(登记的事务到开 `worklet` 段)、`reattach`。归档要收 round、逐个销毁现场,最后才结束段;不排队的话,这中间有人重新打开,归档会去结束重新打开后的新一段,旧的那段永远开着。
