| `Home.tsx` | `Home`:工作台首页,`WorkComposer`(建 work 的输入框,也给拆分子 work 用)、`NewSubwork`(弹窗) |
| `WorkEvents.tsx` | `WorkEvents`:工作页右侧的「轨迹」面板(原来叫「动态」)——这个 work 轨迹的列表视图(`useTrace` → `GET /works/{id}/trace`,OTLP 的段 + 点,5 秒刷新,新的在上;docs/designs/v5/work-trace.md §6):一行是段的开始、段的结束(开着的段只有开始)或一个点,按纳秒时间排(BigInt 比;同一时刻开始 < 点 < 结束,再按接口先后)。`work` 段的开始是创建(带 link / `memorytalk.work.reopened` 的是重新打开),结束是归档;`worklet` 段的开始是打开(在哪一列),结束按 `memorytalk.end.reason` 分关闭(关时在哪一列,`memorytalk.end.column.*`)/ 归档时关闭 / 自己退出了(`gone`,不写谁);点有加 / 改别名 / 删列(`column.*`)、挪动工作单元(`worklet.moved`,分换列和同列换位,第 n 个 = `memorytalk.index` + 1)、关掉时段已经结束了的工作单元(`worklet.closed`,写法同关闭)、改目标(`work.renamed`)、往现场里送了一句 / 按了键(`worklet.input`,只有多长,不存原文)。列标记写成当时的别名或 `列 n`;工作单元叫什么从它的 worklet 段取(点按 `spanId` 找段);每条下面一行是 `谁 · 时间`(开始 / 点取 `user.id`,结束取 `memorytalk.end.user.id`,没有就 `user.id`)。agent 那几层接口默认不给,有 agent / 带记录的工作单元才有按钮,点开再带 `agent=1` 读、只取轮次(`agent.turn`);认不出的段 / 点原样显示名字和属性 |
| `Workspace.tsx` | `Workspace`:一个 work 的页面——头部(目标,右边是除自己外还有谁在看 `Viewers`,来自 `work.viewers`;拆分、归档在侧栏每行的「⋯」里)。在看的心跳就是 `useWork` 15 秒一次的 `GET /works/{id}`;`usePresence` 在关页面(`pagehide`)、换 work、离开工作页时发 `POST /works/{id}/users/leave`(fetch keepalive 带 Bearer;卸载时推到下一拍,StrictMode 的立刻重挂会撤掉它)。下面是**几列,每列从上到下摆工作单元卡片**——列只承载弱编排,没有别的布局对象。`arrange()` 把列清单(`['columns', id]` ← `GET /columns`,按 `position` 从左到右)和工作单元清单(`['worklets', id]`,每个带 `column` / `position` / `collapsed`)摆到一起:每列放 `column` 指向它的工作单元,按 `position` 从上到下;不在任何一列上的(正常没有)补到最左一列末尾。两个清单都 8 秒刷新。编排改动**一个动作一个请求**(`op`:加列 `POST /columns` 带 beside + side、改别名 / 收起列 `PATCH /columns/{c}`、删列 `DELETE /columns/{c}`,交回列清单;挪 `POST /worklets/{w}/move` 带 column + index、收起工作单元 `PATCH /worklets/{w}`,交回工作单元清单),成功就用交回的清单替换对应缓存并刷新轨迹(`['trace', id]`),失败提示并重拉两个清单;编排动作和新建工作单元**排队一个一个发**(同一个 mutation scope `arrange-<id>`,上一个的 onSuccess 跑完下一个才发),后到的回包一定读到了前面所有动作,不会拿旧清单盖掉新的;工作单元可收起、拖动标题上的移动把手挪到任一列任一位置(聚焦把手按方向键也行);列可收起成窄边,空了才能删;列标题有别名只显示别名、没有显示 `列 <编号>`(编号来自列 id,不按位置;前面不带图标),点一下就地改别名(`ColumnName`,无边框输入,编号不动,清空回到 `列 <编号>`);每列底部一排:左边加一列 / 添加工作单元 / 右边加一列;「添加工作单元」弹出 `NewWorklet`(弹层里像浏览器新标签页:上面一条地址栏,块即 URI;下面几块应用,点一块只是把 URI 填进地址栏,回车或「打开」才建),建时带上 `column`,直接进那一列;建好刷新工作单元清单和动态 |
| `WorkletBody.tsx` | `WorkletBody`:一个工作单元的身体——终端(iframe 装 tmuxd 交回的 ttyd 地址)/「轨迹」(claude、bash 的从 trace 读,见 `AgentLog`;Codex / Kimi 还是旧的 rounds)/ 网页 iframe;现场没了时的重连。`WorkletActions`:标题行上的新窗口打开、结束工作单元(先确认;结束后刷新工作单元清单和轨迹) |
| `TraceAnalysis.tsx` | `TraceAnalysis`:轨迹分析页(工作页 `?view=analysis`,右边「轨迹」面板的「分析」打开;`Workspace` 只把各列藏起来,不卸载——心跳和终端照常)。甘特 + 火焰图一根时间轴:甘特一个工作单元一行(worklet 段,开着的画到现在渐隐,`gone` 虚线),最上面是整个工作;点一行展开它的火焰图(`GET …/trace?worklet=&agent=1&fields=spans`,按父子算层:会话 / 轮次 / 工具,出错的红;这个 work 的 `seq` 变了再取)。Ctrl / ⌘ + 滚轮缩放(原生监听,要 preventDefault)、拖动平移、时间轴上框选、点一段放大、双击看全貌;只画视野里的条 |
| `AgentLog.tsx` | `AgentLog`:一个工作单元的「轨迹」页——先整份读 `GET …/trace?worklet=&agent=1&bodies=1`,再带 `seq` 长轮询(`after` + `wait=25`)并进来:人那句、助手的文字 / 思考、工具调用(参数和结果,出错标红)、一轮收尾(耗时、token;bash 是退出码)、换会话;顶上是当前状态(trace 里最新的 `agent.state`)。bash 的写成终端的样子(`$ 命令`、等宽输出)。底下 `Composer`:`POST …/input` 往现场里送(Enter 发,Shift+Enter 换行,输入法选词不算);忙 → 「仍然发送」(force),在等确认 → 去终端 |
| `GlobalSearch.tsx` | `GlobalSearch`:⌘K 弹窗,`GET /search` 按 kind 分组(工作 / 元认知 / 成员),点了就跳 |
