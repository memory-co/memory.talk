# member —— 谁在操作这个 task(v5 设计)

> **状态:框架稿,已有最简实现。** 本篇只立 member 这一层的大框架:member 是**人**,不是现场(现场叫 session,见 [session.md](session.md));它只回答「某个 task 谁当前正在操作、谁历史操作过」,**不做权限**。字段见 [`../../structure/v5/task.md`](../../structure/v5/task.md#member),端点见 [`../../api/v5/tasks.md`](../../api/v5/tasks.md)。

相关:
- v5 task 树(member 挂在 task 上): [task.md](task.md)
- v5 session(现场——和 member 是两个词,别混): [session.md](session.md)
- v5 store(member 是 task 目录下的裸文件): [store.md](store.md)

---

## 1. 一句话:member 让人看到「这个 task 现在谁在动、以前谁动过」

一个 memory.talk 实例是**给一个团队用的**。同一棵 task 树、同一份认知层,团队里的人都在上面干活。这时最常见的问题不是「我能不能动」,而是「**现在有没有别人在动**」「**这件事以前是谁做的**」——前者防止两个人同时往一个 agent 会话里敲字,后者告诉你该去问谁。

member 就是回答这两个问题的记录:每个 task 有一份成员名单,记着**谁、第一次什么时候来、最近一次什么时候来、来过几次**。「当前正在操作」不是一个状态位,是「最近一小段时间内动过」现算出来的。

---

## 2. 不做权限:团队内不限制

这是本篇最重要的一条边界。**所有 task 谁都能操作**;member 只是让人看得见,不是门。

- 没有 owner、没有 assignee、没有「只有 X 能改」。一个人想接手别人的 task,直接动就是;名单上多一个名字,别人一看就知道。
- 没有登录。身份是客户端**自报**的(请求头里带个名字),服务端不校验、不拒绝。团队内互相信任,自报够用;真到了需要鉴权的那天,换成从登录态取名字,member 这层一行不用改。
- 不带身份的请求照样能操作,只是不记名。

为什么这样定:权限系统的成本是永远的——每个端点都要判、每种角色都要维护、每次协作都要先配。一个团队用一个实例,这些成本换不来什么。**看得见就够了**;看得见还出问题,那是沟通问题,不是权限问题。

---

## 3. 什么算「操作」:动了 task 就算,自动记

不要求人「先声明我来了」。任何**带身份**的、会动这个 task 的请求,顺手记一笔:开工、改目标 / 状态、重排画布、打开 / 重入 / 关闭一个 session;**打开 task 本身也算**(读一下就是在看它)。此外有一个显式的心跳端点,给前端「我还开着这个页面」用。

- **不记的**:纯读的列表(看整棵树不算在操作某个 task)、对 card / issue 的操作(那是认知层,谁改了在 git author 里——见 §5)。
- **粒度是 task**,不是 session。「alice 正在操作 task X」,不细到「alice 正在 X 的第 2 个 Codex 会话里」——session 是 tmux,多人 attach 同一个会话本来就是镜像,谁在敲由 tmux 自己解决,不需要 member 再记一层。

---

## 4. 两个视图:current 和 history

```
current : 最近 N 秒内动过的人               ← 「现在谁在这」
history : 动过这个 task 的所有人,按最近活动倒序,每人带 first_seen / last_seen / ops   ← 「以前谁做过」
```

`current ⊆ history`;`current` 是现算的,没有「上线 / 下线」事件——人不需要登出,不动就自然掉出 current。N 先定 2 分钟:前端心跳 30 秒一次,断网、关页面、走开,两分钟后别人就看不到你了。

---

## 5. member 跟认知层的关系:git author

member 只记在 task 上。但同一个人在 task 里争出结果、写了一张卡,那个决定落在 memory 仓库的一个 commit 里——**commit 的 author 就该是这个人**。于是「这条认知是谁定的」不在 member 里,在 git 里;member 回答的是「这件事谁在做」,git 回答的是「这个结论谁下的」。两边用同一个名字(请求头里那个),就能对得上。

> 当前实现 git author 还是固定的服务配置,没有接请求头里的身份——这是下一步,列在 §6。

---

## 6. 这篇有意不定的事

- **身份从哪来**:现在是请求头自报。前端要不要让人在第一次打开时填个名字存本地;将来接了登录态,是替换还是叠加。
- **git author 接身份**:card / issue 的 commit 用请求里的名字当 author(没带就退回服务配置)。做起来很小,但要先定「名字 + 邮箱」怎么给——只有名字时邮箱填什么。
- **活跃窗口 N**:2 分钟是拍的。跟前端心跳间隔一起调。
- **要不要记到 session 粒度**:§3 说不记。如果实践里「两个人同时往一个 agent 里敲」真成了问题,再考虑在 session 上也标一下谁最近 attach 过。
- **history 要不要衰减**:一个 task 活几个月,名单上可能有十几个人。先不管;真长了再按 last_seen 折叠。
