# card —— 本地论的认知卡片(v5 设计)

## 1. 一句话:card 是「一条站住了的认知,连同它在哪成立」

三层里 card 是最静的一层。task 在做,issue 在争,card 是争出结果之后**能带走的那一句**:下次做别的事,想起来的就是它。

所以一张卡只有三样东西:

- **认知本身**:一句可以直接拿来用的话——不是问题(那是 issue),不是「某某说过」(那是论证),是结论。
- **它在哪成立**:一句话说清适用的范围,包括「别用在哪」。
- **它从哪来**:结晶自哪个 issue 的哪个立场,顺着能挖到议事记录和证据。

没有第四样。卡上没有分数、没有状态、没有标签体系——对错在 issue 上(§4),用不用在召回时判(§5)。

---

## 2. 本地论:认知是局部的,所以卡必须带范围

「本地论」是 card 的定义,不是一个附加特性:**没有一条认知在所有场景下都对**。「用户偏好简洁回答」在写代码时成立,在写方案时未必;「这个项目用 LanceDB」在这个仓库成立,换个仓库就是误导。一条不带范围的认知,越被频繁召回越危险——它会被用到不该用的地方,而且用错的时候看起来很自信。

v4 已经碰到了这堵墙(跨场景误用),并用「位」(scope)这个字段去挡([v4 card.md §5](../v4/card.md))。v5 把它从「Position 上的一个字段」提升成**卡的构成要件**:一张卡没写清范围,就不算结晶完成。范围是自由文本、是软提示——召回时随认知一起给 agent,让它自己判当前语境合不合;不做硬门禁,跨界默认放行,只在写明的负边界上提醒。

由此推出 v4 最关键的那条原则在 v5 的位置:**「不该用」≠「错」**。一张卡可能完全正确、但在当前 task 不适用;这是范围的事,不是可信度的事,两者分开判,永远别用一个去代替另一个。

---

## 3. 从 issue 结晶:card 是立场的一个稳定切面

card 不凭空写,它**从 issue 里结晶出来**:一个 issue 底下某个立场被足够多的论证顶起来了,而且能说清它在哪成立,就把它固化成一张卡。

结晶做的事很少:把立场的文本整理成可以直接拿来用的一句话(立场在 issue 里往往是对着问题写的,卡要能脱离问题读懂)、写下范围、记住来源。**结晶不改变 issue**:issue 继续开着,立场继续竞争,manager 继续管;卡只是那一刻的一个切面。

**结晶是一个决定,不是一个阈值。** 可信度可以当提示(「这个立场已经三顶零踩,要不要结晶」),但真正的结晶动作由人或 agent 在 manager task 里做——因为「范围」必须有人写,阈值写不出范围;而且卡应该少而准,自动结晶会把每个稍微站住的立场都变成卡。这就回答了 [README §5](README.md) 和 [issue.md §8](issue.md) 留下的那个问题。

一个立场可以结晶多次:范围写窄了、换了个说法、后来看清了它其实在更大的范围也成立——再结晶一张新卡。旧卡不删、不改(§4)。

---

## 4. 卡自己不打分:对错记在 issue 上

这是 v5 的 card 跟 v4 最大的结构差异。v4 把顶 / 踩计数挂在 Position 上,Position 又是卡的一部分;v5 里**卡上没有计数**——顶 / 踩全部落在 issue 的立场上,卡只是指着那个立场。

为什么这样分:「这条认知对不对」只有一个事实,应该只记在一处。如果卡和立场各记一份,一张卡被踩了、它背后的立场却没变,或者反过来,两边就会漂移。把对错留在 issue 上,card 就可以**完全静态**:结晶那一刻写下的认知和范围,永远不动。

于是:

- **卡的可信度 = 它背后立场的可信度**,召回时现算。立场被新论证顶上去,所有结晶自它的卡一起变可信;被压下去,一起变不可信。
- **卡只增不改。** 认知变了,不是改卡:回到 issue 加一个新立场、打一轮新论证,再结晶一张新卡。旧卡留着,靠它背后旧立场的可信度掉下去而不再被召回;认知史落在 issue 的论证记录上,不落在卡的版本号上。
- **卡没有「过期」「归档」状态。** 一张卡不再该被用,要么是范围写明了(位),要么是背后立场被压下去了(issue)。两条路都不需要卡自己带状态位。

## 5. 召回:卡被注入 task,范围随行

card 是 v5 唯一的**召回单元**。task 开工时(以及 agent 干活途中主动检索时),拿 task 的目标和当前语境去撞卡——撞的是认知文本、范围文本和它背后的 issue 问题;命中的卡按**检索相关性 + 背后立场的可信度**排序,连同范围一起注入 agent 的上下文。

三点沿用 v4 的读路径,只点名:相关性只在召回时算、不回写;范围是软提示、不挡;一个争议 issue 结晶出的对立两张卡,跟当前语境更贴的那张自然排前面,不需要额外的争议判定。

v5 多出来的一点:**卡带着路**。注入的卡告诉 agent 它来自哪个 issue、哪个 task 树——agent 觉得不够用,可以顺着挖:看议事记录、看论证 task 里到底跑了什么。card 是入口,不是全部。

注入的永远是 card,不是 issue 的原文、更不是别的 task 的会话原文。issue 是过程,拿过程去打扰新 task 是噪声;card 是结论,结论才值得占 context。

## 6. 回流:用卡的结果回到 issue,不回到卡

一个 task 用了一张卡,事后发现它对、或者不对——这条证据**回流到 issue 的立场上**(一条带 task round 证据的论证),不写在卡上。卡的可信度下次召回时自然跟着变(§4)。

两条原则再说一遍,因为最容易在回流这一步写错:

- **沉默 ≠ 确认。** 卡被召回、被注入、没被反驳,不产生任何论证。只有 task 里真的顶或真的踩,才回流。
- **「不适用」≠「错」。** 一张卡在这个 task 里被判为范围不合、没用上,这不是踩;顶多是给范围加一条负边界的线索——那也是在 manager task 里改范围、结晶新卡,不是给立场减分。

## 7. 跟 v4 card / v3 insight 的关系

| | 它是什么 | v5 怎么处理 |
|---|---|---|
| **v4 card** | 一个问题 + 若干带 scope 的 Position + 顶踩计数,问题连成 IBIS 图 | **拆成两层**:问题 + 立场 + 论证 + 图 → [issue](issue.md);立场结晶的稳定切面 + scope → 本篇的 card。scope 从立场搬到卡;计数留在立场,卡不带 |
| **v3 insight** | 一句陈述 + rounds 出处,论坛动力学沉浮 | 继续只读可搜,慢慢下掉(同 v4 计划)。可选投影:一条 insight → 一个 issue(它在答的问题)+ 一个立场(它本身)+ 一张卡(补上范围后) |

v4 那条「从最朴素的卡出发、被四堵墙推着长成问题图」的推理全部成立,v5 只是在最后多走一步:**问题图归议事层,认知卡归记事层**,两层各自纯粹——issue 不需要「哪个答案当下可用」的字段,card 不需要「对不对」的计数。

---

## 8. 这篇有意不定的事

- **不经 issue 直接写卡**:人有时就是想直接记一条。允许的话,应该在背后自动生成一个最小的 issue + 立场,让「对错记在 issue 上」这条不破;还是干脆不允许,逼着先提问题。本篇倾向前者,没定。
- **一个立场结晶多张卡的召回**:同一立场、不同范围的几张卡同时命中时,注入全部、还是只注入范围最贴的一张。
- **范围怎么撞检索**:范围文本参与相关性匹配(「当前 task 像不像卡说的场景」)到什么程度;它既是匹配信号又是软提示,两个角色要不要分开。
- **卡的粒度**:一句话是不是永远够;需要带一段说明或一个例子的认知,是放进卡、还是留在 issue 里让 agent 顺路去挖。
- **「本地论」在命名上落不落**:就叫 card 并在定义里说清带范围,还是把「位」提到名字里(比如 scoped card)。同 [README §5](README.md) 最后一条。
