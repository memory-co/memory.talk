# metrics — 记忆质量指标:「真 / 精 / 新 / 召得回」怎么量(v5 设计)

> **状态:设计中。** [README §0](README.md) 说记忆管家(落地实体 = [agent](agent.md))的 loop 为「这套记忆**真不真、精不精、新不新、召得回吗**」而转——这四个词必须可量,否则:自主治理没法验收([agent §3](agent.md) 的影子对照比什么?)、巩固不知道有没有变好、「成功指标 = 记忆质量」是空话。本篇把四维定成**一组 SQL 可算的指标**。

相关:
- 指标的消费者(影子对照 / 回滚判定 / 治理排程): [agent.md](agent.md)
- 指标的载体(全部是预制 SQL / 视图,不是新子系统): [query-interface.md](query-interface.md) · [seekbase.md](seekbase.md)(时光机给曲线)

---

## 1. 三条原则

1. **指标 = 库上现算的 SQL,不是新子系统**:每个指标是一条 query([query-interface](query-interface.md))或一个视图;**历史曲线免费**——seekbase 时光机(`ds_end` 逐天扫)就是趋势图,不必先知先觉地埋点。
2. **不让 AI 自评**(v4 纪律的延伸):验收级指标只用两类——**结构可数的**(占比 / 计数 / 时滞)和 **grounding 在使用行为的**(召回被用上)。「让 LLM 给 corpus 打分」只可作诊断参考,**永远不作验收**——否则自进化的引擎会学会讨好打分器。
3. **每个指标挂一个决策**:不为看板而量。指标要么排治理的工作队列,要么当影子对照的验收线,要么触发告警——三者都不挂的指标不设。

## 2. 四维指标

### 真(grounded)——信念有证据吗

| 指标 | 算法(SQL 概念) | 挂的决策 |
|---|---|---|
| **proof 覆盖率** | 有 ≥1 条 proof 的 card / position 占比 | 低 → 治理优先补证据 / 质疑无据卡 |
| **引证密度** | position 的 review 数分布;零 review 的 position 占比 | 「答案没人表态」的治理队列 |
| **悬空率** | proofs 的 `(type, ref)` 在对应证据面已不存在的比例 | 软引用健康;骤升 = 摄入/删除出问题 |

### 精(lean)——图干净吗

| 指标 | 算法 | 挂的决策 |
|---|---|---|
| **重复度** | `search(issue, …)` 自撞(每卡 issue 搜别的卡):相似度 > 阈值且无边相连的卡对数 | **就是去重工作队列**(治理轮的输入) |
| **矛盾未决数** | 同卡下 credence 接近且对立的 position 对;`replaces` 边两端都活着的数量 | 调和矛盾的队列 |
| **孤岛率** | 无边、无被引的卡占比 | 巩固轮(连边 / 归纳)的输入 |
| **只长不剪斜率** | cards 净增速 vs merge / 墓碑速率 | 长期健康告警(corpus 烂掉的先兆) |

### 新(fresh)——跟得上现实吗

| 指标 | 算法 | 挂的决策 |
|---|---|---|
| **最优答案陈旧度** | `v_card_best` 的答案距最近一条新证据(review / proof)的时长分布 | 「该重审的老结论」队列 |
| **消化时滞** | reality 新 session 落库 → 首次出现在任何 proof 的时间差 | 摄入→结晶的吞吐健康 |
| **未消化积压** | 从未被任何 proof 引用的 session 占比 | 触发结晶轮 / 提示预算不够 |

### 召得回(recallable)——用的时候找得到吗

| 指标 | 算法 | 挂的决策 |
|---|---|---|
| **空命中率** | 检索日志里 top-k 最高分 < 阈值的查询占比 | 高 → corpus 覆盖不了实际问题域 |
| **注入采用率** | hook 注入的卡在该 session 后续被引用 / 被 chat 反馈的比例(近似,§3) | 召回预制 SQL 的调参依据 |
| **分数健康** | semantic 命中分布的漂移(embedding / 阈值退化) | reembed / 调阈值 |

> 召回类指标需要**检索日志**:query 面把 `search()` 调用(查询文本 + top-k 命中 + 分数)落一张 append-only 日志表(insert-only 天然合规)——唯一为指标新增的数据,其余全是现有表上的 SQL。

## 3. 影子对照怎么用它(自主治理的验收)

[agent §3](agent.md) 的「引擎自改 → 影子对照 → 达标才切换」,验收就定在这组指标上。**指标按 agent 实例算**(mind 库每实例一个;真/精/新按各自的 mind,召得回按各自的检索日志),影子对照 = 两个实例在同一 reality 上比:

- **护栏线(不许变坏)**:真类全组 + 悬空率 + 只长不剪斜率——candidate(影子 agent 实例)在同一 reality 上干跑,任何护栏劣化 = 直接否;
- **目标线(要变好)**:本次进化声明要改善哪一两个指标(如重复度),对照组不降 = 不切换;
- **不许比「LLM 觉得好」**(§1 原则 2)。

## 4. 落地形态

- 一组 `v_metric_*` 视图 + 一条汇总(`memory.talk agent mind <name> "SELECT * FROM v_metrics"`);
- **曲线靠时光机**,不靠常驻埋点:`ds_end` 按周扫一遍就是趋势;若全扫太贵,agent 巩固轮顺手往 `metric_snapshots`(append-only 事件表)落一行——快照是**缓存**,真相仍是现算;
- 阈值(相似度 / 分数 / 时滞)全部集中一处声明,好调。

## 5. 待定

- **注入采用率的 grounding**:「被用上」怎么判(后续轮次引用了卡内容?chat 里被确认?)——最难量的一个,先人工抽检定标,再自动化;
- **阈值定标**:重复度 / 空命中的初始阈值拿现有 corpus 标定;
- **诊断层**:LLM 读诊断(如「这两张卡为什么像」)的输出去哪(只进 chat / 报告,不进指标);
- **指标的指标**:护栏被游戏化的风险(引擎学会把卡拆碎降重复度?)——影子对照要看指标**组合**,单指标不作数。
